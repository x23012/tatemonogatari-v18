# たてものがたり アプリ（app/）

ビルド不要の静的Webアプリです。このフォルダをそのまま公開すれば動きます。

## 手元で試す
```
cd app
python3 -m http.server 8765
```
→ http://localhost:8765 を開く（スマホでの確認は同じWi-Fiで `http://<PCのIP>:8765`。ただしカメラとオフライン機能は https か localhost でしか動きません）

## 公開する
1. `app/` の中身を https のサーバーに置く（GitHub Pages、Netlify、Cloudflare Pages など。無料で可）
2. 公開URLが決まったら、カードのQRを作る：
   ```
   pip install qrcode pillow
   python tools/make_qr.py https://公開URL
   ```
   QRの中身は `https://公開URL/?card=<id>`。スマホのカメラで読んでも、アプリ内の読み取りでも追加されます。

## データを変えたとき
- `data/cards.json` はキット直下のものをコピーしています（`photo` の項目はのぞく）。直したら `app/data/` にもコピーしてください。
- 建物の写真は著作権のため、アプリでは使いません（`app/photos/` はありません）。どの画面もイラスト版カードの絵です。
- `illust/`（横360px）は、一覧と読みとり確認に出すイラスト版カード（`ver18/たてものがたり_カード_表_イラスト版.pdf` から切り出し。作り方は `tools/card_images/cut_cards.py` の説明）。
- `art/`（横360px）と `art/l/`（くわしい画面用、横800px）は、選んだ後の画面に出す建物のイラスト（点数や名前のない `ver18/素材_イラスト/` の絵。ファイル名＝カード名を カードID に変えて、sips で縮小：`art/` は画質45、`art/l/` は画質35）。
- `sw.js` の `VERSION` を1つ上げると、スマホに保存された古いデータが入れかわります。
- `lat` / `lng` を入れると、自動で「近い順に並べる」ボタンが出て、Googleマップにも座標で渡すようになります。

## カードを読むしくみ（ver18 のカード）
「カードをカメラで読む」は、QRではなく**カードの見た目**で見分けます（`matcher.js`）。
1. 画面の枠にカードを合わせると、左上の点数マークの色と、カード全体の色・明るさの並びを取り出す
2. 見本（`cards/<id>.jpg`：印刷データから切り出したカード画像）と比べ、近い順に並べる
3. 1位と2位が接戦のときは、四すみの点（`dots.js`）を読んで確かめる
4. 十分近く、2位との差がはっきりしていれば「このカードかな？」を出す。違うときは2位・3位から選べる

### 四すみの点（`dots.js`）
- 左上は点数マーク。右上に1〜2個、左下に1〜2個、右下に1〜3個の点がある（白い細い輪の中に点数の色の点）。
- 点数（色）と3か所の点の数の組み合わせで、カードが1枚に決まる。数は `data/cards.json` の `dots`（[右上, 左下, 右下]）。
- どのすみにも1個目の点はあるので、点のない左上の向きからカードの向きも決まる。
- 点はカードの約1%と小さく、まわりの白い輪も細いので、写真ではぼけて読めないことが多い。読めて自信があり、しかも模様の見分けが接戦のときだけ使う。
- 点の位置を変えたカードを作ったら、`dots.js` の `SLOTS` と、`dots` の数を直してください。`dev/dots-test.html` でテストできます。

## 写真1枚でまとめて読む（`photoreader.js`）
ゲームの最後に、スタンプをのせたままのカードを並べて1枚撮ると、スタンプの数字（＝月）の順にルートを作ります。
1. スタンプ（白い紙の上の色つきの丸）を探す。白い紙に囲まれた丸だけを数える。紙の白さは、丸の中の白い数字の明るさを基準にする
2. 丸の中の数字（1〜12）を、元の大きさの写真から切り出して読む。1人の数字は1枚ずつなので、色ごとに重ならないように割り当てる
3. スタンプのまわりのカードの輪郭を探す（向きは4通り試す）
4. スタンプの紙の白さで色かぶりを直し、スタンプで隠れた所をのぞいて見本と比べる。接戦なら四すみの点で確かめる
5. 確認画面で、写真の切り抜きと見本を並べて表示。自信がない所は黄色。月とカードはその場で直せる

- 写真はプレイヤーの席から撮る前提です（数字の6と9を見分けるため、数字はおおむね上向きとして読む）。
- `dev/photo-test.html` で、写真ごとの読み取り結果を確かめられます。試した写真は `dev/samples/`（git には入れない）。

## どんな旅か（`tripText.js` と `data/trip_text.json`）
ルートの画面のいちばん上と、写真で読んだあとの確認画面に「あなたの旅」を出します。AIは使わず、テーマと文の部品を組み合わせます。
- `trip_text.json` に41のテーマ（お城・徳川家・赤れんが・水辺・明治の建物 など）と、あてはまるカードがある。
- 持っているカードの組み合わせで、いちばん「めずらしい」（偶然にはそろいにくい）テーマをメインにして、タイトルと書き出しを選ぶ。ほかのテーマは「とちゅうでは、〜ます。」に入る。時代のはばの文もつく。
- 同じカードの組み合わせなら、いつも同じ文になる。
- テーマや文を足すときは `trip_text.json` を直す。一覧は `dev/trip-list.html`（ためしにカードの番号を入れて文を作れる）。Word の一覧は `python3 tools/tabi_word/make_docx.py` で作り直せる。

## ファイル
| ファイル | 内容 |
| --- | --- |
| index.html / style.css / app.js | アプリ本体 |
| matcher.js | カードの見た目で見分ける処理 |
| dots.js | 四すみの点を読む処理 |
| tripText.js | 「どんな旅か」のタイトルと本文を作る（data/trip_text.json を使う） |
| photoreader.js | 写真1枚から、スタンプの月とカードをまとめて読む処理 |
| cards/ | 見分け用のカード画像（印刷データから切り出し） |
| dev/test.html | 見分けの精度テスト（開発用） |
| dev/photo-test.html | 写真まとめ読みのテスト（開発用） |
| dev/dots-test.html | 四すみの点のテスト（開発用） |
| dev/trip-list.html | 旅の文のテーマと部品の一覧 |
| sw.js / manifest.webmanifest / icon* | ホーム画面に追加・オフライン用 |
| data/ | カードデータ（キット直下のコピー） |
| illust/ | イラスト版カードの絵（一覧・読みとり確認） |
| art/ | 建物のイラスト（くわしい画面・ルート・ホーム・保存） |
